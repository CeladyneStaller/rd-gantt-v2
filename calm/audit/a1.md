# Parity audit A1: Execution and Sales shell, key results, KPIs, tasks, initiative metrics

(October 15: the Tasks tab built for this audit was removed again, the Kanban covers that work. See
"Execution tasks" below; `mods/tasks` and `test/sc_tasks.js` are gone, initiative metrics are tested by
`test/sc_initm.js`.)

Scope: every item of the Execution checklist (inv/exec.md (a)) and the Sales checklist (inv/sales.md (a)) about
the header and sidebar, selectors and filters, settings, URL parameters, embedding and sign-in, read-only,
broker / load / autosave / conflict / polling, the message bar, the objective header, Sales maintenance, key
results, KPI tables / readings / batches / provenance / targets / linking / Connect data, tasks (exec §17,
never drawn today) and initiative metrics. Files: `apps/exec/*`, `mods/kr`, `mods/kpi`, `mods/tasks`,
`mods/initm`.

Method: the rules were re-read from today's templates (`execution_app.template.html`, `sales_app.template.html`)
and ported into oracles inside `test/audit_a1.js`, which loads its own copy of the engine and drives the built
boards like a person (`out/a1/Main.dc.html`, `out/a1/Sales-A.dc.html`). Examples: today's `objMetricStrip` is
recomputed for every objective of every division; today's `allKpisPool` and `linkCandidates` are re-derived and
compared host by host; every KPI table row is compared with today's `kpiTable` (criterion, current, score,
status word, partial math, override / inherited tag); key result rows with today's `renderKRs` pace and caption
rules. The builders' own tests were not used as evidence.

0 failed (also green on the shared `out/` builds). Evidence `T:A2` = step A2 of `test/audit_a1.js` (step list at
the end); `R:` = verified by reading the cited code.
